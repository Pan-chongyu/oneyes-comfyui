# OneYes ComfyUI OTA

此应用拥有独立的公开仓库和签名身份，不复用或更换 OneYes Desktop / Canvas 的签名密钥。公钥固定在 `desktop/update-key.cjs`。私钥仅保存在本机忽略目录与 GitHub Actions Secret `COMFY_OTA_PRIVATE_KEY`。

正式构建由 `.github/workflows/oneyes-desktop.yml` 按 `oneyes-vX.Y.Z` 标签启动，并使用相同标签发布 Release，与上游引擎版本分开。四个原生 Runner 先安装真实 ComfyUI CPU 环境，核对四种 OneYes 节点、19 个原版节点适配与本地工作流，测试通过后才构建。发布任务汇总 Windows x64 EXE、macOS ARM64 DMG / ZIP、Linux x64 / ARM64 AppImage / DEB / RPM，核对九个安装包并为八种 OTA 目标生成签名清单。

固定更新地址：`https://github.com/Pan-chongyu/oneyes-comfyui/releases/latest/download/comfy-latest.json`，Detached Ed25519 签名为 `.sig`。每种芯片及 Linux 安装格式独立选择；更新前验证清单签名与包 SHA-256。后台每六小时检查并下载，显示进度、失败重试、安装与自动重新打开；Windows 有独立可视化安装助手。

从 0.1.20 起，八种 OTA 格式全部发布有签名清单绑定的 blockmap，按字节复用本机已验证基包中的相同内容，只请求变化区间，流式重建后校验完整安装包。断线保留分块续传进度；索引或数据请求遇到 408、429 和 5xx 时暂停等待用户重试，不转为重复下载整包。基包缺失／损坏、不支持 Range 或重建校验失败才回退完整下载。“关于”显示实际下载量和复用量。旧客户端升级至此版、首次安装或缺少基包索引时仍需完整包；后续具备基包时自动使用增量。

打包只保留定制前端，排除 Python 包内重复的原前端资源，以及固定 CPU 环境不可使用的 CUDA／HIP 编译内核；保留 Python 接口、CPU 内核、原版节点依赖、模板预览和许可证。预编译字节码使用稳定路径，资源归一化文件时间，避免不同构建目录及归档头导致无意义差异；macOS 签名后也归一化时间并再次验证签名。发布前执行 `npm test`、真实账号界面与引擎测试，打包后再次用包内环境执行完整离线工作流并验证 macOS 签名；每个平台运行 `npm run release:blockmaps` 后上传，签名任务缺少任一 OTA 索引就停止发布。测试覆盖八种格式的增量重建、断点续传、Range 降级、暂时故障、损坏包拒绝安装和旧缓存清理。

历史 OTA 包按现有 updater 清理策略保留当前基包和正在下载的新版，其余清理。从 0.1.5 起，完整独立 Python、CPU 依赖和前端随安装包及 OTA 一起提供，不再在用户电脑下载依赖；模型、工作流、任务与 Key 仍位于用户数据目录，覆盖安装不会删除。旧版用户目录的运行环境不再使用，原数据保留。macOS 应用使用 ad-hoc 签名，未经过 Apple 公证；OTA 密码学验证与 Apple 公证是不同机制。

发布前同时运行账号服务测试与 `npm run test:account-ui`，启动真实 ComfyUI，验证免登录直达画布、原生用户页与菜单入口、登录、二次验证、Key 分组选择、复用客户端、切换账号和 IPC 来源限制；在四个平台通过后再打包。账号会话独立加密保存在用户数据目录，与现有 Key 一起在覆盖更新后保留，不随程序包分发。

不要手工覆盖正式 Release 包。发布完成后必须核对公开固定地址签名、九个安装包与应用中心下载 SHA-256。

应用中心介绍和截图按用户长期要求固定维护，基线位于 `docs/app-center/listing.json`，截图使用已提交的固定版本链接。后续同步使用 `scripts/catalog-entry.mjs` 的 `catalogRelease`，读取现有应用后只更新版本、下载包和检测版本；摘要、用途、使用步骤、截图及说明、图标、安装方式与排序全部保留，不以仓库模板覆盖管理后台的人工维护内容。`catalogPresentation` 仅在用户明确要求修改介绍时使用，不能在常规发布路径调用。资料更新不需要更改客户端版本，正式安装包及 OTA 保持原有签名。

发布前运行 `npm run prepare:desktop`、`npm run prepare:runtime`、`npm run prepare:frontend`；运行环境准备只在构建阶段下载并组装固定 Python 3.12.16 与依赖。四个平台必须通过移动到中文 / 空格路径后的离线冷启动测试，并执行全部四类 OneYes 节点和原生工作流。打包后再次导入资源目录内的 PyTorch / 前端依赖，验证实际使用私有 Python 目录；macOS 额外验证启动依赖后签名仍有效。客户端不在应用包内写入 Python 字节码，缓存保存在用户目录。

macOS 的 ad-hoc 签名使用 `scripts/sign-macos.cjs` 顺序扫描 Mach-O 文件并从内到外签名，不将图片、文档或 Python 字节码当作可执行程序；全部资源由最外层应用签名封存，最后执行 `codesign --verify --deep --strict`。

Windows 安装器在安装及静默 OTA 更新后发送 Shell 图标刷新通知；应用身份、安装目录和签名公钥保持一致，旧版本可直接升级到使用 ComfyUI Logo 的新版。

从 0.1.8 起，补齐原版 SPZ v4 点云导入所需的 Zstandard 依赖；要求四个平台在离线搬移后的真实引擎中逐项核对全部原版内置扩展注册，并执行依赖 Kornia、Spandrel、PyAV 和 Zstandard 的代表性节点。打包后再验证包内 Zstandard 可压缩／解压，防止开发环境有包而安装包漏包。依赖变化纳入现有运行环境指纹，旧版环境不能被误判为已经准备完成。

从 0.1.9 起，四个平台额外验证 8 个 ElevenLabs 原版节点定义、工作流导入和本地音色选择器。OneYes 尚未提供的 7 个语音操作保留契约并明确标注不可用，不执行原 Comfy API，也不把它们计为已经接入 OneYes 的生成节点。修复随引擎和前端扩展进入同一签名 OTA。

从 0.1.10 起，菜单退出、Command-Q、系统退出和 OTA 重启均先处理工作流的关闭拦截；用户取消时保留引擎和更新器，确认关闭所有窗口后才停止更新器与后台引擎。清理只执行一次，启动期间退出会等待启动收尾，避免新建遗留进程。四个平台的真实桌面测试必须验证缩到托盘、重新打开、取消退出后本地接口仍可访问，以及确认退出后引擎已停止、程序进程正常结束。

从 0.1.6 起不再提供独立启动设置窗口。单窗口加载引擎后直接显示 ComfyUI 画布，原生“设置 → 用户”集中账户、Key、模型和任务。从 0.1.17 起，软件版本与更新移到“设置 → 关于”，菜单及托盘检查更新跳转到同一页面，保留状态推送、下载进度、安装并重新打开与失败重试。构建阶段从固定 1.59.10 前端生成定制用户及关于面板；预期模块或导出变化时停止构建，禁止静默丢失界面。四个平台验证侧栏与菜单跳转、更新状态及操作按钮，打包后检查关于面板及其模板随同引擎进入安装包和签名 OTA。

从 0.1.21 起，“关于”仅保留产品版本与软件更新，按用户要求移除 macOS 签名说明、页脚／数据目录快捷入口以及原版组件与系统信息折叠区。原版关于面板不再导入或复制，数据目录入口仍可从用户页打开；签名方式与发布验证保持不变。

从 0.1.22 起默认使用简体中文，首次升级会将原英文设置迁移为中文，之后用户手动选择的语言正常保留。使用固定前端自带中文包及 OneYes 本地补充翻译，节点 ID、输入参数名、模型 ID 与工作流格式保持原值。四个平台分别验证新用户、原英文用户、中文设置页／节点和语言切换持久化，打包时核对补充语言文件随引擎进入签名 OTA。

从 0.1.23 起，常用确认与提示使用系统原生对话框，保留原版确认队列、保存／放弃／取消及蓝图“不再询问”设置。桌面层提供文本右键菜单、复制与下载保存选项和任务栏／Dock 下载进度；画布右键、文件上传、工作流数据、节点执行与完整诊断面板不改变。四个平台通过真实前端验证确认返回值、提示框队列、取消时状态保留、文件导出字节一致和 IPC 来源校验后，才生成签名及增量 OTA。

从 0.1.7 起右上角账号按钮与原登录弹窗入口统一为 OneYes。四个平台必须测试实际点击账号按钮、登录状态与余额更新、固定注册／找回密码链接、上游登录入口重定向。OneYes 会话不写入 Comfy Org 身份存储，不会解锁其付费 API 节点。

同一版本的原版节点适配由 OneYes 扩展注册原节点 ID，保留参数与输出类型；仅扩展层发起 OneYes 请求，不修改核心推理实现。发布前测试 OpenAI 异步图片 / Responses、Anthropic Messages、Gemini generateContent、Grok 图片 / 视频协议，核对平台 Key、原尺寸参考图、遮罩、涂鸦、透明通道、重启恢复与不重复提交。缺少上游能力的供应商不冒充可用节点。模型 / 账号缓存、加密 Key 与原任务文件在 OTA 覆盖升级后保留。

从 0.1.24 起，完整包、bsdiff 补丁及 blockmap 差异区间统一使用有界 Range 分块：每块最多 8 MiB，先完成一个网络块确认 Range／ETag，再最多同时处理三块。无需在发布端增加重复的分块文件，八种已签名 OTA 格式直接使用原始安装包与 blockmap。下载按独立偏移写入同一临时文件，每个网络块完成或退出时先同步数据，再原子保存各块偏移；重启时按收据恢复，不能用稀疏文件长度判断已下载。旧版连续 `.part` 缓存迁移为各块进度。当前任务中任一块失败会取消同组请求并保留进度，沿用现有用户重试／定期检查，不新增自动重试规则；408／429／5xx 不降级成完整下载。不支持 Range、Content-Range 或 ETag 不一致时降级为串行兼容下载，仍保留断点续传。

“关于”保留原下载量和复用量，增加已完成／总分块数；下载完成和执行安装前继续验证完整安装包 SHA-256，签名公钥不变，损坏文件不可安装。旧缓存仍随原版本目录清理。发布必须通过真实 HTTP 乱序并发、独立偏移重启恢复、旧缓存迁移、取消、Range 降级、临时故障及完整性测试，并在四个平台通过 Electron `net.fetch` 的实际并行 Range 下载及更新界面验证后生成签名 OTA。

从 0.1.25 起，OneYes 扩展注册原版 `ByteDanceFirstLastFrameNode`，保留节点 ID、输入顺序、可选参数、VIDEO 输出和模板连线；不启用原 Comfy Org 付费代理。新节点可选择 OneYes Video Key 返回的精确 `doubao-seedance-*` ID（含价格别名），旧模板保存的 `seedance-1-*` 保留但不自动映射到其他计费模型，运行前给出选择可用模型的操作提示。原图无损编码且不缩放，水印／音频使用 JSON 布尔值；固定镜头按原节点说明改为提示词指令，避免发送上游不支持的 camera_fixed 字段。接入使用 OneYes `/v1/videos`，既有 Grok 原生任务及去重身份保持兼容。

视频接口支持平面与 code/data 回执、公开结果 URL 及本站 `/v1/videos/{id}/content` 鉴权下载；凭据只发送到固定 OneYes 站点的原任务地址，媒体重定向不携带 Key。下载失败保留完成回执，重启后取回原任务；未知提交不自动重发，回执 ID 不一致立即停止，没有结果地址时给出可重试提示，避免无限等待。发布测试包括中文原工作流导入／模型手动切换、原图尺寸及布尔参数、实际视频解码并保存、完成任务重启恢复，以及鉴权与重定向边界。四个平台打包前及打包后都必须通过真实引擎测试，再发布签名和分块 OTA。

本次适配所依据的接口合同：原版节点 `comfy_api_nodes/nodes_bytedance.py`、[官方节点文档](https://docs.comfy.org/built-in-nodes/ByteDanceFirstLastFrameNode)、[Seedance 接口规范](https://88api.ai/zh/docs/api/video/seedance-multi-resolution/)与现有 OneYes 统一视频请求适配。实机只读核对 Video Key 模型目录；执行回归使用隔离测试传输，不将其描述为真实付费生成验证。
